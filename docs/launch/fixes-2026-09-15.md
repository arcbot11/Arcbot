# Launch implementation follow-up — 2026-09-15

Local changes following `review-2026-09-15.md`. Launch execution remains hard-disabled. No deployment, signature, public message, or live transaction was performed.

## Changes

- The launch editor's missing client directive was fixed in the preceding change and checked with the installed Next.js server-component compiler.
- Deployment calls can use up to 5,000,000 gas through the shared sender. The exception requires validated launch terms, the correct owner, destination and calldata, and enabled execution. Ordinary calls retain the 1,000,000 limit. The full sequence retains its 0.5 USDC total gas ceiling. Transaction persistence and pre-signing validation enforce the launch envelope policy again.
- Busy wallets, unavailable images, changed blocks, stale simulations and bounded mining failures remain retryable. Changed image bytes and other invalid terms still stop unsigned work. Started signatures retain their original recovery path.
- Accepted runs have a 30-minute authorization deadline. X deadlines derive from the original command's creation time, not worker retry time. New steps and pre-signing checks enforce it; the Convex signing mutation atomically cancels never-signed work if authorization expires or the run stops. Recovery of an existing signing attempt remains possible after expiry.
- Signing compares the raw estimated execution gas against the saved buffered allowance. It no longer rejects a harmless increase solely because it applies a second 20% buffer. An estimate above the saved allowance stops before signing and requests new review.
- Repeated preparations reuse the accepted hook salt only when its creator, token salt and init-code hash match. Live Portal prediction, address-mask, bytecode and implementation checks remain in place.
- Paired launch valuation checks both V3 and the recorded Argus V4 pool. Candidates are compared using virtual USDC reserve depth. The local admission threshold is at least 1,000 USDC and 20 times the requested developer buy. Material candidate pools (at least 10% of selected depth) disagreeing by more than 10% cause rejection. USDC launches require no market conversion.
- Empty discovery now reports an incomplete result if the Convex registry failed. The website retains previously discovered tokens for that same wallet while retrying incomplete reads; complete reads can remove obsolete entries.
- Completed launches no longer count against the ten active-draft limit. The separate short-term request limit remains.

## Remaining readiness checks

- Once Arc RPC access works, re-verify the selected Portal 6 deployment and live transaction simulation, then test the complete setup/approval/launch/receipt/indexing flow before enabling customer launches.
- Paired valuation still uses a pinned spot price and virtual reserve depth, not a TWAP or oracle. Concentrated liquidity may span narrow tick ranges, and a single market can still be manipulated. The new checks prevent the reproduced dust-pool selection error; they do not establish manipulation-resistant pricing.
- Full preparation still repeats live state and image checks before signing. Hook mining is reused, but live launch latency has not been measured during this outage.

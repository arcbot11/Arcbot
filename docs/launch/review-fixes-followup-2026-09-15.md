# Launch review follow-up fixes — September 15, 2026

Launch execution remains disabled. No deployment, signing, broadcast or production configuration changes were made.

1. **X retry classification:** temporary launch errors now return `pending: true` and `processing: true` at the actual Arc command API boundary. Convex continues its existing retry chain instead of finalizing the wallet request as failed. Definite validation errors remain final; durable recovery still decides the outcome of accepted transactions.
2. **Hook review:** preparation verifies the Portal's `hookStore` address and stored bytecode against a source-controlled review registry, both before mining and after a refreshed head. This applies during pre-signing checks too. There is no automatic enrollment or environment override. **The registry is deliberately empty:** the saved ABI bundle documents the mutable hook but supplies neither compiled bytecode nor independently reviewed store code. Preparation now stops with `HOOK_REVIEW_REQUIRED` until that evidence is obtained, reviewed and pinned. This closes the unreviewed-code path; it does not constitute completed bytecode review.
3. **Lost website responses:** confirmation records a wallet-scoped tracking marker before the request. Read-only polling starts even if the POST response is lost or an early GET still sees a prepared draft. Refresh restores that tracking. Once the durable run appears, normal run polling takes over. Retrying uses the same request ID; no background resubmission is introduced. A user may cancel an unaccepted draft, using Convex's atomic refusal to cancel an already accepted run.
4. **Terminal drafts:** safe stops and reverted/cancelled steps update the draft to cancelled in the same mutation as the blocked run. Completed launches allow New draft immediately. Old terminal runs are reconciled out of the active draft quota during creation. In-flight signing remains protected; an expired running launch cannot be replaced through the UI.
5. **Execution copy:** the page and review panel describe transaction authorization when execution is enabled; preparation-only copy remains accurate while disabled.
6. **Paired valuation:** ARGUS and ARCASH keep V3/V4 support. The chosen liquid USDC pool must also have sufficient liquidity at timestamped 5-, 15- and 30-minute checkpoints. Current and historical prices must stay within 10% of the historical median. Conversion uses that median, not the current spot. Historical block lookup is bounded and deduplicated; block hashes are checked again and reference evidence is stored with the quote. Missing archive state, sparse history, price disagreement or changed blocks cannot fall back to spot pricing. USDC avoids these lookups entirely.

The historical check limits transient price manipulation; it is not an independent oracle or a proof of manipulation resistance. A sustained manipulated market can pass historical checks. Archive RPC availability and funded launch behavior still require live verification after Arc access returns.

Regression coverage includes the actual social API boundary, unchanged signing locks, terminal lifecycle/quota repair, uncertain-response tracking rules, both execution-copy states, changed/unreviewed hook stores, historical pricing, thin historical liquidity, missing archive reads and reorgs.

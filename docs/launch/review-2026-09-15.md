# Launch review — 2026-09-15

Scope: local launch implementation, X command integration, website preparation/execution, shared transaction signing/recovery, paired-asset valuation, receipt checks, indexing and creator-fee discovery. No deployment or transaction was performed. Launch execution remains disabled. This is not a production activity audit.

## Findings

1. **High — launch editor fails Next.js server-component compilation.** `components/LaunchPreparation.tsx:4` imports React hooks without a `use client` directive. Its importing page is a server component. Reproduced with the installed Next.js SWC server-component transform. The disabled runtime flag does not remove the import from compilation. Restore the client boundary and include a framework compilation check.

2. **High — shared sender rejects deployment-sized gas.** `lib/launches/prepare.ts` permits 5,000,000 gas while `lib/otc/runtime.ts:114` uses the hardcoded 1,000,000 limit in `lib/project-config.ts:10`. Reproduced with the actual `prepareCall` function and a mocked 3,000,000 gas estimate. Recorded Portal 6 examples used 3.3–3.6 million gas. Use a narrowly scoped launch gas policy throughout preparation and signing. A generic rejection before transaction persistence leaves the accepted run retrying.

3. **Medium — temporary failures permanently stop accepted launches.** `lib/launches/service.ts:27` handles every `LaunchError` as a terminal stop, including `WALLET_BUSY` and transient `IMAGE_UNAVAILABLE`. Reproduced both an occupied wallet and an image outage after a completed approval. The run becomes blocked and its worker stops retrying. Separate transient failures from changed, invalid or revoked authorization; keep the existing signing fence.

4. **Medium — paired-launch price selection can ignore the real market.** `lib/launches/quote.ts:33` only checks V4 when V3 liquidity is exactly zero. Reproduced a V3 pool with one liquidity unit suppressing all V4 discovery. The selected spot price sets the creator-buy quantity and initial/bond valuations. Compare viable market depth and reject unreliable or materially inconsistent prices. USDC launches do not use this conversion.

5. **Medium — accepted X runs bypass the new-transaction authorization timeout.** `lib/launches/social-service.ts:24` checks the 30-minute authorization age only when no accepted run exists. `lib/launches/service.ts:74` rechecks ownership but does not expire permission for a new signature. After a long outage, an accepted run can still begin a new transaction using its old frozen quote. Continue recovery for prior signatures, but bound authorization for new steps and expose a safe unsigned stop path.

6. **Medium — small gas-estimate increases can stall signing unnecessarily.** `lib/launches/service.ts:85` compares a newly buffered estimate to the previously buffered gas limit. An initial estimate of 100,000 stores 120,000 gas; a later estimate of 100,001 produces 120,002 and is rejected, although the estimated execution fits the saved limit. This generic error retries the same unsigned transaction until its 15-minute cancellation threshold. Compare actual required gas with the stored allowance or safely rebuild before signing. Full preparation and hook mining are also repeated for each step and again before signing.

7. **Medium — creator-fee discovery still has a false-empty path.** `lib/launches/fee-service.ts:21` returns before setting the incomplete diagnostic when no candidates were returned. Reproduced a failed Convex registry query plus an empty Argus feed: the result was an empty list without an incomplete flag. A recent creator whose token is not yet on the feed loses the fee controls without the intended retry. Set discovery status before all returns and preserve known tokens on incomplete reads.

8. **Medium — completed launches exhaust the draft quota.** `convex/launchDrafts.ts:47` counts every unexpired non-cancelled record toward ten active drafts, including completed launches. Completed records cannot be cancelled. Reproduced ten completed records preventing a new draft, even though none were active. Count only unfinished drafts/runs, preserving the separate short-term rate limit.

## Verification and limits

- The existing targeted launch, parsing, API, identity and social regression tests passed.
- Additional mocked diagnostics reproduced the gas-policy mismatch, terminal handling of temporary failures, V3-over-V4 selection, false-empty discovery and completed-draft quota.
- Next.js SWC compilation failed on the missing client declaration. TypeScript/unit-test success is not a production build pass.
- Inspected the authorization-age and gas-buffer paths directly; these were not tested with real signatures.
- The public Argus RPC receipt probe returned non-JSON content; no new live receipt confirmation is claimed. The gas examples above come from the saved research records.
- Inspected the current published Argus ABI bundle and Next.js client-boundary documentation. A funded end-to-end launch remains untested and is required before enablement.
- Review only: no application fixes, deployment, signing, public messages or transactions.

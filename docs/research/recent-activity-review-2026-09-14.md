# Activity review — 14 September 2026

Window: **07:31–13:31 UTC / 04:31–10:31 ADT**, six hours. Read-only review of the configured Convex application backend, with subsequent chain/explorer checks. Activity after the snapshot cutoff is excluded from the counts. No keys were retrieved, transactions submitted, or live records changed.

## Main findings

### Token discovery is incomplete, with confirmed explorer omissions

All **13 Telegram balance responses across seven users** contained the partial-token-refresh warning. Native USDC values were returned, but token completeness was not established. This is not equivalent to 13 failed Telegram commands: all responses were delivered.

During the follow-up check, the Arc Explorer address-token endpoint returned HTTP 200 with `items: []` for two affected wallets and for Odysseus. A direct on-chain read at block **20828353**, 13:36 UTC, showed Odysseus held **142,350.539567058759383122 BABYARGUS**. The explorer omission is therefore real for at least that wallet.

The holdings implementation retries empty explorer responses, probes a rotating batch of indexed tokens, and always checks known/pinned addresses. This helps recover balances, but cannot guarantee discovery of every holding if the explorer returns no inventory and the token is absent from that request's known/pinned/batch set. Its retained-balance cache is process-local. Successful empty responses also deliberately become `partial`, which can give truly empty wallets the same warning.

Recommended priority: persist known token holdings from transactions, seed every balance request from those records, and distinguish “inventory discovery incomplete” from an individual balance read failing. Removing a warning alone would not resolve missing holdings.

### Arc trading delays remain

Three swaps and six associated approvals completed. All three swaps were from Odysseus: a 1 USDC ARGUS buy, an ARGUS sell, and a 2 USDC BABYARGUS buy. The latest sell took **3m 16s**, and the latest buy **4m 41s**, measured from first approval record to swap completion. Initial previews are excluded.

As documented in the separate [trade timing review](trade-speed-review-2026-09-14.md), delayed broadcast/recovery and repeated approvals dominate the long cases. Post-mining verification completed within roughly 4–10 seconds. Read-only Infura-first quote experiments were substantially faster, but those results do not demonstrate complete execution support through tracing.

An earlier available log sample recorded an OTC recovery worker failure at **13:20:14 UTC** during this sequence; a subsequent worker run succeeded. The underlying provider error was not retained in the available Convex log. No transaction remains pending in the reviewed snapshot.

### Two Telegram buys returned misleading insufficient-funds wording

Two users submitted 10 USDC ARGOS buys. Both received:

> Not enough tokens for the amount plus token tax. Use a smaller amount or 100%.

Neither produced a transaction record. The response is generated by the input-balance guard, but it uses sell-oriented token-tax wording even for a USDC buy. It should identify the input asset and required amount. Historical funding sufficiency was not independently reconstructed, so this review does not claim the rejection itself was erroneous.

### Export audit can label a later close request as failed after successful delivery

There were **three acknowledged export flows: two X, one Telegram**. Each has requested → identity verified → approved → export started → response authorized → client acknowledged events.

The Telegram flow was acknowledged at **10:17:24.902 UTC**, then logged `failed:close:EXPIRED` at **10:18:50.762 UTC** for the same grant. The close mutation revokes the grant after acknowledgment; subsequent access fails the expired/revoked guard. This is not evidence of a failed key delivery. A repeated close should be handled or classified idempotently so monitoring does not flag a completed export as failed. No grant, export confirmation, or execution lock was left active in the reviewed snapshot.
